# Practical assessment — written answers

**1. Metaobjects, metafields and tags.** Use a Colour metaobject for its reusable name, hex and swatch, and Finish for its name and optional image. Product metafields reference those records; integer metafields hold each product’s permitted dimensions. This gives typed data and one place to correct a finish or swatch. Use native variant options for thickness and edge, since they select a purchasable price. Tags suit temporary merchandising groups or import tracking, rather than dimensional rules or structured colour data.

**2. Theme migration and rollback.** Duplicate the current theme and record its ID, settings, app embeds, navigation and critical journeys. Test an unpublished staging theme with representative products, collections, search, cart, contact forms and mobile/keyboard users. Preserve product and collection handles; export existing redirects and add permanent redirects only where URLs change. Compare titles, descriptions, canonical/noindex rules, headings and Product/Breadcrumb JSON-LD, including pagination and filters. Measure the same pages with Lighthouse and validate Rich Results. Publish only after approval, monitor errors and conversions, and retain the previous theme for immediate rollback. Theme rollback does not restore changed catalogue data, redirects or app settings; back up and reconcile those separately.

**3. Checkout price differs from the product page.** Reproduce the exact product, variant, dimensions, currency/market and discount. Compare the displayed breakdown with `/cart.js`: Shopify’s variant price, quantity, properties, line discounts and subtotal. Here quantity is the number of 0.01 m² units, rounded upward; it is not the number of worktop pieces. Confirm the product page, cart and schema use that same unit. Then check cart transforms, selling plans, Functions/apps, market price lists, exchange rates, tax inclusion, shipping and rounding. Trace the first stage that differs, correct the shared cause and regression-test variant changes, fractional area, repeated pieces and tampered requests. Never repair a price by trusting a browser-supplied total.

**4. Re-runnable import of 200+ products.** Validate a versioned manifest first: stable external product IDs/handles, unique variant SKUs, option combinations, prices, integer limits, metaobject references and image ownership. Create or reconcile definitions and reusable metaobjects before product values. Upsert by stable identifiers and store returned Shopify IDs; use paginated/bulk reads for reconciliation, bounded batches, rate-limit backoff and checkpoints. Reuse existing file IDs rather than uploading duplicate images on every run. Dry-run a diff, import a small staging sample, then verify counts, variant prices, publication, references and completed media processing. Guard against destructive list replacement, duplicate SKUs, handle collisions, stale concurrent edits, partial failures and async operation errors. Keep an audit log and a backup; archive deliberately removed records only after review. Retry only failed operations with the same identifiers.
